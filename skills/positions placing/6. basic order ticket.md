Implement Task 6: Basic Order Ticket UI only.

Context:

* Trading foundation is done.
* Shared trading models/store are done.
* REST account snapshot sync is done.
* Binance user data stream sync + reconnect/reconciliation is done.
* Order placement and cancellation are still not implemented.

Goal:
Add the basic order ticket UI, but do not execute orders yet.

1. Add order ticket panel

Create a compact order ticket UI for the active chart/panel.

It should support:

* Buy / Sell toggle
* Market / Limit order type
* Quantity input
* Price input for Limit orders
* Reduce Only toggle if supported by current model
* selected symbol display
* selected trading mode display
* testnet/live badge

2. Market vs Limit behavior

For Market order:

* hide or disable price input
* show estimated execution price using latest/last chart price if available

For Limit order:

* show editable price input
* default price can use latest/last chart price

3. Validation only

Add frontend validation:

* quantity must be greater than 0
* limit price must be greater than 0
* symbol must exist
* trading mode must exist
* live mode must show blocked/disabled if live trading is not enabled

4. Confirmation modal

When user clicks Buy or Sell:

* open a confirmation modal
* show side, symbol, order type, quantity, price if limit, mode, and testnet/live badge
* final confirm button should still not place an order yet

For now, final confirm should show a safe message:

`Order execution is not implemented yet.`

5. No backend order execution

Do not implement:

* place order route
* cancel order route
* modify order route
* Binance order API calls

Existing `placeOrder()` and `cancelOrder()` must still reject as not implemented.

6. State

Store order ticket UI state in non-persisted runtime/UI state unless there is already a clean local component state pattern.

Do not persist:

* quantity
* side
* order type
* price
* confirmation state

7. UI placement

Place the order ticket where it fits current app layout.

Keep it simple:

* either right-side trading panel
* or compact floating/order panel
* or collapsible panel if existing UI pattern supports it

Do not redesign the whole layout.

8. Use existing account/snapshot data if available

Show available balance if already present in runtime snapshot state.

If balance is unavailable, show a neutral empty/loading state.

Do not create new snapshot logic.

9. Do not change chart systems

Do not change:

* chart rendering
* indicators
* market data feeds
* footprint/profile logic
* drawing tools
* existing settings
* user stream logic
* REST snapshot logic

10. Validation

Run:

`npx.cmd tsc --noEmit`

Expected:

* basic order ticket UI exists
* Buy/Sell, Market/Limit, quantity, and limit price UI work
* confirmation modal opens
* no orders are actually submitted
* existing order methods still reject as not implemented
* no API secrets are exposed

Implement Binance testnet user data stream sync with reconnect and state reconciliation.

Context:

* Trading foundation exists.
* `/api/trading/health` exists.
* `/api/trading/account-snapshot` exists.
* Binance testnet account snapshot can fetch balances, open orders, and recent fills.
* Order placement and cancellation are still disabled.

Goal:
Add read-only live account update sync from Binance testnet/demo, plus safe reconnect and reconciliation.

Do not implement order placement UI yet.

1. Add backend user stream manager

Create a server-side user data stream manager for Binance testnet/demo.

It should:

* start the Binance user data stream
* connect to the correct testnet/demo WebSocket endpoint
* receive account/order/trade events
* normalize events into existing app trading models
* never expose API secrets to the frontend

2. Handle supported events

Normalize events for:

* balance/account updates
* order updates
* trade/fill updates
* execution reports

Update the app’s trading runtime state shape using the existing models:

* balances
* openOrders
* positions
* recentTrades/fills
* connection status
* last stream event time

If futures positions are not supported yet, keep positions empty but structure the code so futures can be added later.

3. Add reconnect logic

If WebSocket disconnects or errors:

* mark stream status as disconnected/reconnecting
* reconnect with backoff
* avoid duplicate parallel streams
* clean up old sockets/listeners
* keep the latest connection status in debug/runtime state

4. Add keepalive / session renewal

If the selected Binance stream method requires listenKey keepalive:

* renew before expiry
* handle expired listenKey by recreating the stream
* reconnect automatically after renewal/recreation

Use safe timers and cleanup.

5. Add state reconciliation

After reconnect, do not trust only missed WebSocket events.

Run REST reconciliation by calling the existing account snapshot flow.

On reconnect:

* refresh balances
* refresh open orders
* refresh recent trades
* merge/replace runtime state safely
* avoid duplicate fills/orders

6. Add backend stream status route

Add a safe route like:

`/api/trading/stream-status`

Return:

* trading mode
* stream status
* connected/reconnecting/error
* last event time
* reconnect count
* last error message
* listenKey/session status if applicable

Never return secrets.

7. Add frontend stream state

Extend non-persisted trading runtime state with:

* userStreamStatus
* userStreamConnected
* userStreamLastEventAt
* userStreamReconnectCount
* userStreamLastError
* reconciliationLoading
* lastReconciledAt

Do not persist this state.

8. Add debug info

Add safe debug fields:

* tradingMode
* accountSnapshotConnected
* userStreamConnected
* userStreamStatus
* userStreamLastEventAt
* reconnectCount
* lastReconciledAt
* balancesCount
* openOrdersCount
* positionsCount
* recentTradesCount

9. Keep order actions disabled

Do not implement:

* place order
* cancel order
* modify order
* order ticket UI
* chart order lines

Existing `placeOrder()` and `cancelOrder()` must still reject as not implemented.

10. Do not change unrelated systems

Do not change:

* chart rendering
* indicators
* market data feeds
* footprint/profile logic
* drawing tools
* settings
* collectors

11. Validation

Run:

`npx.cmd tsc --noEmit`

Expected:

* backend can start and monitor Binance testnet user data stream
* frontend/runtime can receive live account/order/fill updates
* reconnect works without duplicate sockets
* after reconnect, REST account snapshot reconciles state
* no API secrets are exposed
* no orders can be placed yet

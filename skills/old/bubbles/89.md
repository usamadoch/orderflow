Implement Aggregate Trade Bubble Min Orders filtering and explicit Spot/Futures handling.

Context:

* Volume Bubbles currently support:

  * Footprint Cells
  * Aggregate Trades
* Footprint Cells are the default and should not be changed.
* Aggregate Trades are live-only and rendered from Binance aggTrade events.
* Aggregate Trades currently support:

  * Size By: Volume / Orders
  * Min Volume
  * Side Filter
  * Scale Mode: Linear / SQRT / Log
  * Min Radius / Max Radius
* Aggregate BubbleEvent already includes optional `tradeCount`.
* Debug snapshot exists at `window.__MARKET_DEBUG__.getSnapshot().aggregateBubbles`.

Goal:
Add proper Min Orders filtering when Size By = Orders, and make Spot/Futures handling explicit for Aggregate Trade bubbles.

Do not implement tooltip, persistence, grouping/clustering, raw trades, iceberg logic, or historical restore in this task.

1. Add/verify Min Orders filter behavior

When:

* Bubble Source = Aggregate Trades
* Size By = Orders

Then:

* Show `Min Orders` setting in UI.
* Hide or disable `Min Volume` because it is not the active filter in Orders mode.
* Filter aggregate bubbles using `event.tradeCount >= bubbleMinOrders`.
* Size/radius should also use `event.tradeCount`.

When:

* Bubble Source = Aggregate Trades
* Size By = Volume

Then:

* Show `Min Volume`.
* Hide or disable `Min Orders`.
* Filter aggregate bubbles using `event.volume >= bubbleThreshold`.
* Size/radius should use `event.volume`.

Missing/invalid tradeCount:

* Treat missing/invalid `tradeCount` as `1`.
* If `bubbleMinOrders > 1`, these fallback events should be filtered out.
* Report fallback count and filter reasons in debug output.

2. Add explicit Aggregate Bubble Market Source setting

Add a new setting for Aggregate Trade bubbles only:

`aggregateBubbleMarketSource: 'active' | 'spot' | 'futures' | 'both'`

UI label:
`Market Source`

Only show this when:

* Bubble Source = Aggregate Trades

Options:

* Active Chart
* Spot
* Futures
* Both

Default:
`active`

Meaning:

* `active`: use the currently selected chart contract/source behavior.
* `spot`: show only spot aggregate trade bubbles.
* `futures`: show only futures aggregate trade bubbles.
* `both`: show spot and futures aggregate bubbles together.

3. Source filtering behavior

Each Aggregate BubbleEvent should have:

* contractType: `spot` or `futures`
* symbol
* source: `aggregateTrade`

Renderer should filter aggregate bubbles by `aggregateBubbleMarketSource`.

Rules:

* If `active`, use current chart/panel contractType or current active market source. Keep this behavior backward-compatible with how the app currently works.
* If `spot`, render only events where `contractType === 'spot'`.
* If `futures`, render only events where `contractType === 'futures'`.
* If `both`, render both spot and futures events.

Do not merge or rewrite event prices.
Aggregate bubbles must continue using actual aggTrade event price.

4. Prevent stale cross-source bubbles

When symbol changes:

* Clear aggregate bubble buffer.

When market source/contract type changes:

* Clear or filter safely so old source bubbles do not appear incorrectly.

If using separate buffers per source is cleaner, implement separate buffers:

* spot aggregate events
* futures aggregate events

If keeping one buffer, make sure filtering by contractType is correct and no stale source leakage happens.

5. Optional visual source distinction for Both mode

If easy and safe:

* Slightly distinguish spot vs futures bubbles in Both mode, for example with border style or opacity difference.

But do not overbuild this. If it risks complexity, skip visual distinction and just ensure filtering is correct.

6. Debug updates

Update aggregate bubble debug snapshot to include:

* aggregateBubbleMarketSource
* current active chart contract/source
* total aggregate events by source:

  * spot count
  * futures count
* visible/rendered count by source
* filter reasons:

  * below min volume
  * below min orders
  * excluded by market source
  * excluded by side filter
* latest rendered event contractType
* latest rendered event volume
* latest rendered event tradeCount
* sizing mode and sizing value used

7. Do not change existing systems

Do not change:

* Footprint Cell bubble logic
* Footprint aggregation
* Footprint storage/restore
* Aggregate bubble persistence/history
* Raw trade support
* Grouping/clustering
* Tooltip behavior
* Iceberg logic

8. Validation

Run:

* `npx.cmd tsc --noEmit`

If lint has unrelated existing failures, mention them but do not fix unrelated files.

Expected result:

* Aggregate Trades Volume mode keeps working as before.
* Aggregate Trades Orders mode properly uses Min Orders and tradeCount.
* User can choose Aggregate Bubble market source: Active Chart, Spot, Futures, or Both.
* Spot/futures aggregate bubbles are filtered clearly and safely.
* Debug output explains exactly why bubbles rendered or were filtered.
* Footprint Cells remain unchanged.

Implement Aggregate Trade Bubbles as a second bubble source.

Do not remove or break the existing Footprint Cell bubble system. Keep Footprint Cells as the default and backward-compatible mode.

Goal:
Add a new live-only bubble source where bubbles are drawn directly from Binance aggregate trade events instead of footprint cells.

Current system:

* Existing bubbles are based on footprint cells: candle time + price bucket + askVol/bidVol.
* Existing source is labeled as Footprint Cells.
* Existing scale modes, min/max radius, threshold mode, side filter, and min volume already work.

New behavior:
Add support for:

Bubble Source:

* Footprint Cells
* Aggregate Trades

When Bubble Source = Footprint Cells:

* Keep current behavior exactly as-is.

When Bubble Source = Aggregate Trades:

* Draw bubbles from live Binance `aggTrade` events directly.
* Each bubble should represent an aggregate trade event/aggressive execution cluster.
* Do not aggregate it into footprint cells first.

Create a separate BubbleEvent model/type, for example:

* time
* price
* side: buy/sell
* volume
* tradeCount if available from aggTrade IDs
* source: aggregateTrade
* symbol
* contractType: spot/futures

Add a live rolling buffer for aggregate trade bubble events:

* Keep this in memory only for now.
* Do not add database persistence yet.
* Do not change footprint storage or restore API.
* Keep a reasonable max buffer size, for example 5,000–20,000 events per panel/source.

Use Binance aggTrade data:

* price from aggTrade price
* volume from aggTrade quantity
* side from buyer maker logic:

  * buyerMaker false = aggressive buy
  * buyerMaker true = aggressive sell

Rendering:

* Add renderer/source switching:

  * Footprint Cells → existing drawBubbles path
  * Aggregate Trades → new draw aggregate bubble events path
* Reuse existing visual settings where possible:

  * min volume
  * side filter
  * scale mode: linear/sqrt/log
  * min radius
  * max radius

Filtering:

* For aggregate trade bubbles, min volume should apply to the individual aggregate trade event volume.
* Side filter should work for buy/sell/both.
* Do not add min orders yet.
* Do not add size-by orders yet.

Important restrictions:

* Do not implement raw trade bubbles yet.
* Do not implement iceberg logic.
* Do not implement historical persistence yet.
* Do not implement grouping/clustering yet.
* Do not change footprint cache behavior.
* Do not change footprint cell bubble behavior.
* Do not merge aggregate trade bubbles into footprint cells.

Expected result:

* User can switch Bubble Source between Footprint Cells and Aggregate Trades.
* Footprint Cells behaves exactly like before.
* Aggregate Trades shows live aggressive execution bubbles directly from Binance aggTrade events.
* TypeScript should pass.
* Existing bubble settings should still work.

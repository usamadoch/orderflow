## Task 2: Add Aggregate Trade Bubble Source

**Main next task.**

This adds a second real bubble mode:

```txt
Bubble Source:
- Footprint Cells
- Aggregate Trades
```

Instead of drawing bubbles from footprint buckets, this will draw bubbles from Binance `aggTrade` events directly.

Why it matters:

```txt
Footprint Cell Bubble = volume accumulated in a price bucket
Aggregate Trade Bubble = aggressive execution event / cluster
```

This is closer to DeepCharts-style execution bubbles.

---

## Task 3: Create Bubble Event Model

You need a separate data structure for trade-event bubbles.

Example fields:

```ts
time
price
side
volume
tradeCount
source
contractType
symbol
```

This keeps aggregate trade bubbles separate from footprint cells. Without this, the code will become messy.

## Task 4: Add Live Bubble Event Buffer

Start live-only first. No database yet.

Store recent aggregate trade bubble events in memory:

```txt
aggTrade stream → BubbleEvent → rolling buffer → renderer
```

Example:

```txt
keep last 5,000–20,000 events per panel
```

This lets the chart draw recent aggregate-trade bubbles without touching footprint storage.

## Task 7: Add Size By: Volume / Orders

This can come after aggregate trade source works.

For Binance `aggTrade`, you can estimate trade count from:

```ts
tradeCount = lastTradeId - firstTradeId + 1
```

Then setting becomes:

```txt
Size By:
- Volume
- Orders
```

Volume means bubble size based on quantity.
Orders means bubble size based on number of trades inside the aggregate event.

---

## Task 8: Add Min Orders Filter

After `tradeCount` exists, add:

```txt
Min Orders
```

Example:

```txt

```

This helps detect aggressive bursts made of many executions, not just one large quantity.
